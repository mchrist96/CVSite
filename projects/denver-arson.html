Denver Arson Clustering

A geospatial clustering project using Denver crime data to compare KMeans and DBSCAN, with a focus on arson incidents and the trade-offs between Euclidean and spherical distance.

Tools: Python • pandas • NumPy • scikit-learn • Matplotlib • SQL Server • QGIS

Overview

Denver publishes a large open dataset containing reported crimes and geographic coordinates. I used this data to investigate whether clustering methods could identify meaningful spatial patterns in arson incidents.

The project compares two approaches. KMeans uses Euclidean distance and requires the number of clusters to be specified in advance. DBSCAN instead identifies dense regions, can treat observations as noise, and can use the Haversine distance to better represent distances between latitude/longitude coordinates.

Data & Preparation

The original crime dataset contained more than 500,000 records and 19 fields. I filtered the data to the Arson offense category, leaving 719 coordinate observations for clustering. SQL Server was used for filtering and Python was used for modeling.

The Python workflow connects directly to SQL Server and reduces the dataset to the latitude/longitude coordinates required by the clustering algorithms:

server = 'DESKTOP-00EIBV3'
database = 'Crime Data'

conn = pyodbc.connect(
    'DRIVER={ODBC Driver 17 for SQL Server};'
    'SERVER=' + server + ';'
    'DATABASE=' + database + ';'
    'Trusted_Connection=yes;'
)

sql = "SELECT * FROM [Denver Crime] WHERE OFFENSE_CATEGORY_ID = 'arson'"
crime_data = pandas.read_sql(sql, conn)
coordinates = crime_data[['GEO_LAT', 'GEO_LON']].to_numpy()

KMeans

KMeans assigns every observation to a cluster, so the first question is how many clusters to use. I used the Elbow Method to compare within-cluster sum of squares across candidate values of K. The resulting curve suggested four clusters.

wcss = []
for k in range(1, 10):
    model = KMeans(n_clusters=k, init='random', algorithm='full')
    model.fit(coordinates)
    wcss.append(model.inertia_)

plt.plot(range(1, 10), wcss)
plt.title('The Elbow Method')
plt.xlabel('Number of Clusters')
plt.ylabel('WCSS')
plt.show()

With four clusters selected, I fit the final KMeans model and exported the cluster assignments and centroids for visualization in QGIS.

DBSCAN

DBSCAN provides a useful contrast because it does not require a predefined number of clusters and can explicitly identify noise. Because latitude and longitude lie on a sphere rather than a flat Cartesian plane, I used the Haversine metric with coordinates converted to radians.

dbscan = DBSCAN(
    eps=1 / 6371.008,
    metric='haversine',
    algorithm='ball_tree',
    min_samples=6
)

dbscan.fit(np.radians(coordinates))

After experimenting with the neighborhood radius and minimum sample count, the selected parameters produced a substantially different structure from KMeans: dense groups were identified while roughly 10% of observations were treated as noise.

Geospatial Visualization

To move beyond scatter plots, I exported the cluster assignments and coordinates for use in QGIS. This made it possible to overlay the results on a map of Denver and inspect the spatial structure of the models.

Key Takeaways

  • KMeans: produced four clusters and assigned every observation to one of them.
  • DBSCAN: identified dense regions without requiring a predefined cluster count and separated noisy observations from those regions.
  • Distance matters: using Haversine distance is more appropriate than treating latitude/longitude as ordinary Cartesian coordinates.
  • Visualization matters: moving the results into QGIS made the geographic structure considerably easier to interpret than model output alone.

This project was primarily an exploration of geospatial analytics and clustering methodology. The models identify statistical patterns in reported incidents; they should not be interpreted as causal explanations or predictions of future crime.
