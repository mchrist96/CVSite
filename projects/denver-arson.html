Denver Arson Clustering

A geospatial clustering project using Denver crime data to compare KMeans and DBSCAN, with a focus on arson incidents and the trade-offs between Euclidean and spherical distance.

Tools: Python • pandas • NumPy • scikit-learn • Matplotlib • SQL Server • QGIS

Note: Some of the original images and portions of the original project write-up were unfortunately lost over time. As a result, this page has been repurposed as a shorter summary of the project, with some of the original analysis and implementation details condensed or omitted.

Overview

I used Denver's public crime data to investigate whether unsupervised learning could identify meaningful spatial patterns in reported arson incidents. The project compares KMeans, which requires a predefined number of clusters, with DBSCAN, which identifies dense regions and can classify observations as noise.

Data & Preparation

The original crime dataset contained more than 500,000 records across 19 fields. I filtered it to the Arson offense category and retained records with geographic coordinates, leaving 719 observations for clustering. SQL Server handled the initial filtering and Python handled the modeling.

sql = """
SELECT *
FROM [Denver Crime]
WHERE OFFENSE_CATEGORY_ID = 'arson'
"""

crime_data = pandas.read_sql(sql, conn)
coordinates = crime_data[['GEO_LAT', 'GEO_LON']].to_numpy()

KMeans

KMeans assigns every observation to a cluster, so the first modeling decision is the value of K. I used the Elbow Method to compare within-cluster sum of squares across candidate values. The curve suggested four clusters as a reasonable balance between model complexity and fit.

wcss = []
for k in range(1, 10):
    model = KMeans(n_clusters=k, init='random')
    model.fit(coordinates)
    wcss.append(model.inertia_)

plt.plot(range(1, 10), wcss)
plt.xlabel('Number of Clusters')
plt.ylabel('WCSS')
plt.show()

DBSCAN

DBSCAN provides a different approach. It does not require the number of clusters to be specified in advance and can identify observations that do not belong to dense regions. Because latitude and longitude represent positions on a sphere, I used the Haversine distance rather than treating the coordinates as ordinary Cartesian values.

dbscan = DBSCAN(
    eps=1 / 6371.008,
    metric='haversine',
    algorithm='ball_tree',
    min_samples=6
)

dbscan.fit(np.radians(coordinates))

After testing the neighborhood radius and minimum sample count, the selected model identified dense regions while treating a meaningful subset of observations as noise. This was useful for distinguishing concentrated spatial patterns from isolated incidents.

Geospatial Visualization

I exported the cluster assignments and coordinates to QGIS to inspect the results geographically. Mapping the clusters provided more useful context than model output alone and made the differences between density-based and centroid-based clustering easier to interpret.

Key Takeaways

  • KMeans provided a simple partition of the incidents into four spatial groups.
  • DBSCAN offered a more flexible view of the data by identifying dense regions without requiring a cluster count and separating noise.
  • Distance selection matters for geographic data; Haversine distance better represents separation between latitude/longitude coordinates.
  • Visualization is critical for geospatial analytics. QGIS made the model outputs substantially easier to interpret in geographic context.

This project was an exploration of geospatial analytics and clustering methodology. The models identify statistical patterns in reported incidents; they should not be interpreted as causal explanations or predictions of future crime.
