My Own Spotify Wrapped

A personal analytics project recreating and extending Spotify Wrapped using my own listening history. I combined SQL and R to compare listening behavior by plays and by total time spent.

Tools: SQL Server • R • RODBC • ggplot2 • JSON

Overview

Spotify's annual Wrapped experience summarizes a user's listening habits, but the underlying listening-history data contains enough detail to build a more customized analysis. I used Spotify's exported data to answer questions about listening volume, unique artists and tracks, and my top artists and songs.

The central question became whether number of plays or time spent listening gives a better picture of my listening habits. This distinction matters because songs vary dramatically in length.

Getting the Data

Spotify allows users to request their historical listening data through their privacy settings. The export contains JSON files with the timestamp, artist, track, and milliseconds played for each listening event. My export contained roughly 30,600 streams across four streaming-history files.

Loading the Data into SQL

I loaded each JSON file into SQL Server and converted the nested JSON records into a relational table. This created a single ListeningHistory table that could be queried consistently throughout the analysis.

DECLARE @JSON varchar(MAX);

SELECT @JSON = BulkColumn
FROM OPENROWSET(
    BULK 'FILE LOCATION',
    SINGLE_CLOB
) AS import;

SELECT * INTO ListeningHistory
FROM OPENJSON(@JSON)
WITH (
    [endTime] date,
    [artistName] nvarchar(MAX),
    [trackName] nvarchar(MAX),
    [msPlayed] int
);

Cleaning & Initial Analysis

I removed podcast entries so the analysis focused exclusively on music. I also removed plays shorter than 10 seconds, treating those events as skips rather than meaningful listening sessions.

DELETE FROM ListeningHistory
WHERE msPlayed < 10000;

SELECT
    COUNT(DISTINCT artistName) AS Unique_Artists,
    COUNT(DISTINCT trackName) AS Unique_Tracks,
    AVG(CONVERT(bigint, msPlayed) / 1000.0) AS Avg_Time_Played_Sec
FROM ListeningHistory;

The cleaned dataset contained 1,125 unique artists and 5,088 unique tracks, with an average of approximately 145 seconds per play.

Connecting SQL and R

For the more involved analysis I connected R directly to SQL Server using RODBC. This allowed SQL queries to feed directly into R objects and made it easy to combine database aggregation with visualization and cumulative calculations.

library(RODBC)

con <- odbcConnect("Spotify Data")
Spotify_Data <- sqlQuery(
    con,
    "SELECT * FROM ListeningHistory"
)

Top Artists: Plays vs. Time

I calculated the top 10 artists by number of plays and tracked their cumulative totals throughout the year. I then repeated the analysis using total milliseconds listened rather than play count.

top_artists <- sqlQuery(con,
    "SELECT TOP(10) artistName, COUNT(*) AS Total
     FROM ListeningHistory
     GROUP BY artistName
     ORDER BY Total DESC")

The rankings changed noticeably when switching from plays to time. Longer songs, particularly metal tracks, accumulated far more listening time than their play counts suggested.

Top Tracks

I repeated the same comparison for individual tracks. The difference between the two ranking methods became even more pronounced: shorter tracks could accumulate many plays quickly, while long tracks could dominate when measured by total listening time.

Key Findings

  • Play count and listening time tell different stories. Rankings changed substantially when switching the metric.
  • Track length introduces a strong bias. Shorter rap and punk songs can accumulate plays much faster than long metal tracks.
  • Time-based rankings better captured the prominence of long-form listening. Several metal artists moved substantially higher when measured by total time.
  • The distinction was even stronger at the track level. The play-based top 10 favored shorter songs, while the time-based ranking favored longer tracks.

Future Directions

A natural extension would be to enrich the listening history with genre and track-length data. That would allow analysis by genre, normalize listening into fractional plays, and more directly reproduce the genre-oriented analysis found in Spotify Wrapped.
